## Domain entrypoints observed October 2

The repeatable `pnpm check:domains` probe records exact redirect chains in `../website/.evidence/domain-entrypoints-live.json`. Its latest October 2 run found **zero redirect gaps** across seven entrypoints, and all seven canonical HTTPS homepages returned 200. Plain HTTP redirects to the same HTTPS host for Digifender (308), Whumpo (308), ChapelCloud (308), OpenHost (301), LabThrift (301), Lab plan (301) and ByteRush (301). Whumpo and ChapelCloud returned 308 for a non-root path and query. OpenHost returned 301 for the same HTTP probe; its HTTPS `www` host returned 308 to the apex with path and query preserved. Before the Whumpo and ChapelCloud fixes, `http://whumpo.com/` returned 404 and `http://chapel.cloud/` served 200 over HTTP. The OpenHost preview deployment added managed website DNS, leaving its existing mail records intact.

The optional `www.whumpo.com` and `www.chapel.cloud` names did not resolve in the same probe; no current company or Whumpo source link to either name was found. `www.labthrift.com` served a 200 page with a canonical link to the apex. Treat these as branding/routing observations until the product owners decide whether those hostnames should be public entrypoints.

The operator Cloudflare API token used by Whumpo's existing deployment scripts could inspect both active zones. Neither had a zone Single Redirect ruleset or an account Bulk Redirect entrypoint; both apex DNS records were proxied and zone-wide Always Use HTTPS was off. This task created one [zone Single Redirect](https://developers.cloudflare.com/rules/url-forwarding/single-redirects/create-api/) per apex: `(http.host eq "whumpo.com" and not ssl)` or `(http.host eq "chapel.cloud" and not ssl)`, with a dynamic `concat("https://<same host>", http.request.uri.path)` target, status **308** and `preserve_query_string: true`. API readback showed both rules enabled in version 1: Whumpo rule `49525cd6de9e4cc49e4e687298037954` and ChapelCloud rule `850977e90e7f4a4990c8c6aca2f08027`. Live root and path/query probes passed, and the sampled HTTPS homepages remained available. Cloudflare's Page Rules endpoint rejected this account-owned token with error 1011, so legacy Page Rules could not be enumerated; [Cloudflare documents Single Redirects as taking precedence over Page Rules](https://developers.cloudflare.com/rules/url-forwarding/). This limits the precedence inventory, while the new rules match only plain HTTP requests for these two apex hosts. The shared Wrangler OAuth token alone had returned 403 for rulesets and Page Rules. Sanitized rule readback and live probes are saved in `../website/.evidence/domain-redirects-release-2026-10-02.json`.

- Keep each product's own name and visual identity. Add a small, readable “A Digifender product” link to <https://digifender.com/> in the shared footer or account frame; do not imply that pending filing or unsigned documents are complete.
- Show direct, product-specific Terms and Privacy links in the footer and before account or data-collection decisions. Add the product's Cookies/Storage link where that notice applies. The current collection routes are <https://digifender.com/legal/whumpo>, <https://digifender.com/legal/chapelcloud> and <https://digifender.com/legal/labthrift>.
- Label the current Digifender-hosted product documents as **drafts**. Do not turn a draft link into a claim of accepted or effective terms, replace an existing effective agreement without review, or add an acceptance checkbox until the product owner completes its legal adoption steps.
- Route legal, privacy, copyright and abuse requests to the company legal contact already published in the relevant documents. Show a separately owner-verified inquiry or support route for each product; remove the ChapelCloud `.example` placeholder before relying on its consult call to action. A working MX or forward rule alone does not prove monitored correspondence.
- Keep policy wording in the source listed in the product map. Publish the company legal copy from that source and verify the product label, title, draft state, canonical destination, reciprocal company link and desktop/mobile placement after each release.
